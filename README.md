# A*Board

A*Board is an A Level study companion for **previewing** topics before class and **reviewing** them afterwards with spaced repetition. It covers AS and A Level topics common to the major boards (Cambridge International, Edexcel, AQA, OCR) in English Language, Mathematics, Physics, Chemistry, Biology and Geography.

- **Frontend:** plain HTML, CSS and JavaScript, with no framework and no build step.
- **Backend:** Python with Flask and SQLite.

## Run it on your computer

Requires **Python 3.10 or newer**.

```bash
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python app.py                      # then open http://localhost:3000
```

Stop the server with `Ctrl + C`. To start again with an empty database (this deletes all accounts), delete the `data/` folder.

Environment variables:

- `PORT` sets the port (default 3000).
- `DATA_DIR` sets where the SQLite database is stored (default `./data`).
- `FLASK_ENV=production` adds the `Secure` flag to cookies. Set it when the site is served over HTTPS.
- `GAME_MIN_LEVEL_MS` sets the shortest time a game level can be cleared in (default 10000).
- `TRUST_PROXY=1` reads the visitor's IP from the hosting platform's proxy. Set it on Render and similar hosts.

## Features

1. **Preview:** each topic has a primer, key terms and three guiding questions. Marking a topic as previewed adds its flashcards to the learner's review deck.
2. **Review:** the learner types an answer, compares it with the model answer, then grades the card Again, Hard, Good or Easy. Cards are rescheduled with an SM-2 style algorithm.
3. **Practice:** each topic has a multiple-choice paper, marked on the server, with an explanation for every question.
4. **Dashboard:** cards due, today's reviews, streak, points, progress in each subject and recent scores.
5. **Reward game, Print Breaker:** learners earn points by studying and spend them on a five-level brick-breaker.

### Points and the reward game

| Rule | Value |
|---|---|
| Grade a review card | +1 point |
| Answer a quiz question | +1 point per question, on the first sitting of each topic per day |
| One run of Print Breaker | costs 5 points, 3 lives |
| Clearing a level | saves a checkpoint: the next run starts there |
| Beating level 5 (*The A\**) for the first time | **+30 points** and the *A\* Champion* badge; the board then resets to level 1 |
| Upgrading the badge (champions only) | Rubber Stamp (won) → Riso Sticker 20 → Stitched Patch 40 (4 lives per run) → Foil Seal 70 → Holo Card 120 (5 lives per run) |

The game is drawn on a `<canvas>` by `public/js/game.js`. The server owns the points: it deducts the cost, checks that each cleared level is the one being played, and ignores a level cleared faster than `GAME_MIN_LEVEL_MS` (default 10 000 ms). The values, including the badge tiers (`BADGE_TIERS`), are constants at the top of the points section in `app.py`. Databases from older versions gain the badge column automatically on start-up.

The interface uses frosted-glass panels over drifting riso shapes, with tactile feedback: stamped button presses, ink bursts, flipping and flying review cards, and counting numbers. All motion is switched off for visitors who ask their system for reduced motion.

## API

| Method | Path | Purpose |
|---|---|---|
| POST | `/api/auth/register` · `/login` · `/logout` | Accounts. Passwords hashed with scrypt; sessions in HttpOnly cookies |
| GET | `/api/me` | The current user, or `null` |
| GET | `/api/catalogue` | Public list of subjects and topics |
| GET | `/api/dashboard` | Stats for the dashboard |
| GET | `/api/subjects/<slug>` | A subject's topics with the learner's progress |
| GET | `/api/topics/<id>` | Primer, terms and guiding questions |
| POST | `/api/topics/<id>/preview` | Marks the topic as previewed and adds its cards to the deck |
| GET/POST | `/api/topics/<id>/quiz` | Fetch the questions (without answers) / submit answers for marking |
| GET | `/api/review?subject=slug` | Cards that are due |
| POST | `/api/review/<card_id>` | Submit a grade `{ "grade": 0-3 }`; earns 1 point |
| GET | `/api/game` | Points, checkpoint level, champion status |
| POST | `/api/game/start` | Spends 5 points and returns a `runId` |
| POST | `/api/game/clear` | `{ runId, level }`: records a cleared level; awards the grand prize after level 5 |
| POST | `/api/game/end` | `{ runId }`: ends a run (out of lives or left the page) |
| POST | `/api/badge/upgrade` | Spends points to raise the champion badge one tier |

## Changing content

1. Edit `server/content.json`. Add new topics at the **end** of a subject's list so existing learners' progress stays attached to the right cards.
2. The database is filled from this file only when it is empty. To reload it locally, delete the `data/` folder (this also deletes accounts). On a live site with real users, write a small migration instead.
3. Run `python3 demo/build.py` to regenerate the GitHub Pages version in `docs/`.

## Putting it online

**Quick and free (no accounts on a server):** in the GitHub repository, open **Settings → Pages**, choose **Deploy from a branch**, select branch `main` and folder `/docs`, then click **Save**. The site appears at `https://<username>.github.io/<repo>/`. In this version accounts and progress are stored only in each visitor's own browser.

**Full site with real accounts (Render or similar):** create a Web Service from the GitHub repository with:

- Runtime: Python
- Build command: `pip install -r requirements.txt`
- Start command: `gunicorn app:app`
- Environment variables: `FLASK_ENV=production`, `TRUST_PROXY=1`, `DATA_DIR=/var/data`
- A persistent disk mounted at `/var/data`. Without one, every redeploy wipes all accounts.
